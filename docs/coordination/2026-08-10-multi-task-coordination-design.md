# 平衡步兵多任务协作约定

日期：2026-08-10

## 目标

允许理论研究、仿真验证、代码解读等 Codex 任务独立推进，同时避免任何任务完全不了解其他任务正在做什么、已经得到什么结论以及存在哪些冲突。

## 职责边界

- 用户自行创建、命名和关闭独立 Codex 任务。
- 当前任务作为总控台，不代替用户创建任务。
- 总控台负责识别相关任务、读取阶段进展、汇总全局状态、转发依赖信息和提示结论冲突。
- 各专业任务只对自己的分析和产物负责，不默认拥有其他任务的完整上下文。

## 推荐命名

- `平衡步兵｜总控台`
- `平衡步兵｜理论建模`
- `平衡步兵｜仿真验证`
- `平衡步兵｜代码解读`

统一前缀便于总控台从任务列表中准确识别同一项目的任务。后续可以继续增加机械参数、测试记录、文献核验等任务。

## 同步流程

1. 用户创建新任务后，在总控台告知任务名称，或直接说“同步所有平衡步兵任务”。
2. 总控台读取相关任务的最新状态和最近阶段总结。
3. 总控台形成一份全局摘要，并发送给需要了解该信息的其他任务。
4. 各任务继续工作前，应优先采用最新全局摘要；发现与自身假设冲突时，向总控台报告，不自行静默覆盖。
5. 任务完成阶段性成果、改变关键假设、产生仿真结果或发现代码事实后，再由总控台进行一次同步。

## 统一状态格式

每次同步尽量包含：

- 当前目标
- 已完成内容
- 证据或产物位置
- 采用的关键假设
- 尚未解决的问题
- 对其他任务的影响
- 下一步
- 需要总控台或用户决定的事项

## 结论标记

跨任务传播的结论必须标记为以下状态之一：

- `已验证`：有推导、仿真、源码或实验数据支撑。
- `部分验证`：只有部分条件或场景得到支持。
- `待验证`：当前只是合理假设或资料中的说法。
- `存在冲突`：不同任务的模型、参数、代码或实验结果不一致。

## 同步触发条件

出现以下情况时需要同步：

- 一个阶段完成或工作方向变化。
- 理论模型的状态量、符号、坐标系或假设发生变化。
- 仿真结果支持或否定理论结论。
- 代码事实与文档、理论或仿真假设不一致。
- 参数、接口或文件修改会影响其他任务。
- 任一任务遇到需要其他任务提供信息的阻塞。

## 限制

独立 Codex 任务并不天然共享实时记忆。跨任务了解依靠总控台读取和广播，因此目标是保证每次继续关键工作前获得最新摘要，而不是声称所有任务在每一秒都自动同步。
